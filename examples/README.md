# 示例：按用途选择作品

Show how it works.

Joplo 的作品由 Agent 用代码写成，能播放，也能上手试。这里按观众要看懂什么来选入口；组件与文件结构不是用途分类。功能下面的作品仍叫“方案 / option”。

## Before you build it / 动手之前

**Design the behavior before you build the feature.** 比较一个功能的几种方案，把各种情况走一遍，留下规则。

主打：[团队邀请](invite)。同一目标下有单人邮件弹窗与独立页面批量邀请两种方案，情况包括正常邀请、权限不足、无效邮箱与撤销；规则、覆盖与选定都有对应内容。它能直接说明为什么在实现前比较方案，而不只是展示一条成功流程。

## How it runs / 它怎么运转

一套架构、一条调用链、一次代码变更。

主打：[Agent 架构](agent-arch)。同一次任务连接客户端、大脑、端侧执行器、云端沙箱与计费；分组架构图、时序、状态与 `trace()` 从不同视角解释谁执行、谁等待，以及额度不足、端侧离线等情况。它比只展示一张静态架构图更能说明系统怎样运转。

## What happened / 发生了什么

一个故事、一则新闻讲解、一段产品历程。

主打：[同一个按钮的 40 年](button-40-years)。同一个发送按钮串起 1984—2024 四套风格化界面，观众能暂停输入、拖动年代，再继续播放；连续镜头和原创配乐服务于“交互方式怎样改变”的产品历程。它无需实时新闻背景，也能把时间变化讲清楚，适合作为这一用途的第一入口。
