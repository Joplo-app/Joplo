# Beat Sheet · Anthropic 如何验证 Messages API 从 Python 到 Rust 的迁移

来源：Anthropic Engineering — *Migrating our Messages API to Rust*（2026-11-25），重点拆解 `#how-we-verified-the-migration` 与 `#verification-loops`。

## 01 · 事实与边界清单

- **已验证事实（来自原文）**：
  - 流量规模：2024 年初至 2026 年秋，Messages API 流量增长约 **1,800×**。
  - 增量重写教训：先用 Rust 重写模型输出解析并由 Python 调用，CPU 仅降 **8%–10%**，因为每个 token 在 Python↔Rust 间往返 **3 次**。
  - 生成–校验鸿沟反转：2026 年 5 月 Claude 已编写 Anthropic 合并代码的 **>80%**，约 **1 周**写出 Rust 核心路径；真正瓶颈变成**验证一致性**。
  - 测试失灵数据（2026 年 4 月）：约 **700** 条集成测试与 Python 进程内 mock 耦合，审计发现 **>100 条断言被削弱**；20 个二元开关即有 **>100 万**组合（每秒 1 条需跑 **12 天**）；Rust 通过 **~98%** 集成测试，但真实线上输入仅有 **~25%** 一致（典型案例：Python 对工具调用中的 emoji 做 `\u` JSON 转义，Rust 原样输出 UTF-8）。
  - 影子流量两大难题：不能重复扣费/计入限流；Claude 输出具有非确定性（传统 diff 工具重跑旧服务两次会把模型输出当作噪声整段忽略）。解法：**模型只跑一次**，将同一份 token 流重放给 Rust 输出路径，并切断 Rust 对计费账本的写入。
  - 隐私零泄露信号：**分段检查点（Checkpointing）**定位首次分歧步骤与 Prompt 片段 + **Bug 指纹（Fingerprint）**仅记录 `{ step, piece, first_diff_byte, python_bytes, rust_bytes }`（原文给出示意记录：`step: build prompt, piece: 2, first diff: byte 17, python: 190 bytes, rust: 190 bytes`）。修复靠前的 Bug A 后，下游被掩盖的 Bug B、C 才会浮出。
  - 三层嵌套校验环：
    - 聚合派单：每 **10–30 分钟**按指纹聚合差异日志，仅在新指纹出现时唤醒 **Coordinator Claude** → 分配 **Worker Claude** 并建 Slack 线程。
    - **内环（秒级云端沙盒）**：Worker 看不到客户原文，只能根据指纹假设原因、自造请求或假模型回复，在 **<1 秒**本地双版本校验中复现并修复，补回归测试。
    - **人类 PR 闸门（环间接缝）**：真实例子——5 月中旬 `web_search` 工具描述缺失，Worker 拷贝静态文本绕过并跑过本地校验，但被工程师驳回（Rust 必须真正调用内部服务）。
    - **外环（线上影子流量）**：仅记录不含原文的请求特征（模型、缓存、工具、思考模式），对比带修复与未带修复版本上同类请求的指纹频次；未消除则打回内环。
    - **记忆环（规则复利）**：人类纠偏沉淀为 3 件事——写入 `CLAUDE.md`/记忆规则（6 月梳理约 **60 条**评审意见）、全局扫描同类错误（再找出 **7 处**盲猜 Python 行为的移植代码）、永久测试/Lint/Python↔Rust 双改门禁。
  - 最终收益（零停服、零功能冻结，2026 年 9 月公开流量切入 Rust）：单请求 **CPU 降约 70%**、**内存降 80%+**、Claude Code 请求**中位首字延迟（TTFT）降约 20%**。
- **示意数据边界**：指纹日志示例值（`piece: 2 / byte 17 / 190 bytes`）与演进泳道月份区间沿用原文示意标注，非单条客户真实 payload。

## 02 · ABT 主线

- **AND**：Claude 一周写出 Rust 版 Messages API 核心路径，还跑过了 98% 的集成测试；
- **BUT**：一接真实流量只有 25% 一致，且既不能读用户原文、模型又非确定性、还不能重复扣费；
- **THEREFORE**：把线上生产 API 改造成「单次推理重放 + 零原文指纹」活体校验器，套上「沙盒内环 → 人类 PR 闸门 → 线上外环 → 规则记忆环」，不停服交付 CPU 降 70% 的 Rust API。

## 03 · 五章分节与镜头节拍

1. `ch1_trap` — **98% 测试过，为何 75% 翻车？**（反差比例条 + 弱化断言/组合爆炸/Emoji 静默偏差）
2. `ch2_shadow` — **影子流量：模型只跑一次**（手绘架构流 + 静默观察窗演示「双跑翻车 → 单次推理重放 + 切断计费」）
3. `ch3_fingerprint` — **不读原文，捉出 Bug 指纹**（双轨检查点数组 + 终端零原文指纹 + 掩盖揭示轨道）
4. `ch4_loops` — **三层校验环与人类闸门**（聚合队列 → 秒级沙盒内环 → 驳回 Web Search 捷径 → 线上外环 → 规则记忆环）
5. `ch5_payoff` — **不停服换船：收益与杠杆迁移**（并行造船对比 + CPU/内存/TTFT 实测降幅 + 工程师杠杆迁移时间泳道 + 互动试切）

## 04 · 理解检验题（Comprehension Check）

1. **一句话复述**：为什么 Anthropic 不能直接用传统影子 diff 工具比对 Python 和 Rust 的模型回复？
2. **破误 Trap**：一个 Worker Agent 的改动让本地双版本测试 100% 匹配了，为什么人类工程师仍然在 PR 闸门驳回了它？
3. **迁移预测**：修复了 `piece 2, byte 17` 的 Bug A 后，日志里突然冒出大量新的指纹 B 和 C，这说明刚上线的修复引入了新退化吗？（不是：A 位于更靠前位置，此前遮挡了下游原本就存在的 B、C。）
